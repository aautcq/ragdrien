# Fetch and clean Documents from web pages

Until now every Document under `lib/rag/documents/` was hand-authored. Keeping documents like a LinkedIn profile in sync with their source page meant manually copy-pasting and reformatting them. We added `scripts/fetch-document.ts` (`pnpm fetch-document <url> <filename.md> [--force]`) to fetch a web page, extract its readable content, and have the same local Ollama chat model rewrite it into a clean Markdown Document, written directly into `lib/rag/documents/`.

Notable choices and their trade-offs:
- **Extracting readable content with Readability (`@mozilla/readability` + `jsdom`) before handing it to Ollama**, rather than sending the raw fetched HTML straight to the model. Raw HTML includes nav/scripts/ads/styles that would bloat the prompt and produce noisier output; pre-extraction narrows the model's job to "reformat this article as Markdown" instead of "find the article first". The trade-off is that pages whose content is rendered client-side via JavaScript (a plain `fetch` never executes it) will fail extraction outright — acceptable for a manually-run, occasional import tool, but worth knowing if a target page turns up empty.
- **Reusing the chat model via `resolveOllamaConfig`**, rather than a separate configurable model for this cleanup task, for the same premature-optimization reasoning as ADR 0003/0004: nothing has shown a need for a different model yet.
- **A minimal hand-rolled frontmatter parser** (`source`/`fetchedAt` flat keys only) in `lib/rag/documents.ts`, rather than adding a dependency like `gray-matter`, since the format has no nested structures or arrays to justify one.
- **Denormalizing `sourceUrl` onto every `RagChunk`** (mirroring how `documentId` is already denormalized per-chunk) rather than threading a separate `documentId → metadata` lookup through `retrieval.ts`/`route.ts`, keeping the existing per-chunk shape as the single source of provenance.
- **Streaming the AI SDK's built-in `source-url` part instead of `source-document`** when a Source has a known origin, rather than bolting a non-standard `url` field onto `source-document`. This means `app/page.tsx` handles two source part shapes, but stays within the SDK's documented stream schema instead of inventing one.
- **Failing outright rather than silently degrading** at every step (unreachable page, no extractable article, empty/unreachable Ollama, existing file without `--force`): this is a manually-run tool, so a clear error to fix and re-run beats a partially-written or silently-empty Document sitting in the corpus.
